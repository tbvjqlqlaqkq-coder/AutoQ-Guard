# AutoQ-Guard 공개데이터 검증 점검 — 2026-09-03

## 결론

기존 고정 규칙의 결과는 재현되었다. 그러나 예측 성능을 확정하기 전에 관찰기간, 원본 정보의 공개 시점, 리콜 집계 단위를 보완해야 한다. 이번 작업은 기존 자료에 대한 재검증이며 새로운 독립 시험이 아니다. 경보규칙과 원본 CSV는 유지했다. 이번 업데이트에서 실행 경로와 검증 상태 표시를 수정했다.

## 직접 실행한 결과

- 월별 패널: 175,344행
- 브랜드·모델·연식·부품계통·월 중복: 0행
- 저장된 ALERT와 문서의 고정 규칙 재계산 불일치: 0행
- 기존 시험구간 2025-01~2026-06: 40,464행
- TP 132, FP 1,513, FN 1,392, TN 37,427
- 정밀도 8.02%, 재현율 8.66%: 기존 보고서와 일치

위 수치는 월별 그룹 관측치 단위다. 리콜 캠페인 포착률이나 예방 차량 대수가 아니다.

## 중요 발견 1: 12개월 관찰기간

패널 마지막 월은 2026-06이다. 결과 자료도 이 시점까지만 완전하다고 가정하면, 12개월 미래 평가에 포함할 마지막 관측월은 2025-06이다. 실제 결과 자료의 수집 마감일과 월 경계 규약은 별도로 확인해야 한다.

가정에 따라 기존 시험구간을 2025-01~2025-06으로 제한한 민감도 분석:

| 항목 | 전체 기존 시험 | 관찰기간 제한 시나리오 |
|---|---:|---:|
| 관측치 | 40,464 | 13,488 |
| 정밀도 | 8.02% | 10.80% |
| 재현율 | 8.66% | 5.84% |
| TP / FP | 132 / 1,513 | 42 / 347 |
| FN / TN | 1,392 / 37,427 | 677 / 12,422 |

제외 후보는 26,976행이다. 제한 결과는 저장된 Y12를 그대로 사용한 조건부 분석이며, 새로운 정확도 확정값 또는 성능 개선이 아니다. 다른 기간의 원시 비용 합계끼리는 비교하지 않는다.

## 중요 발견 2: 리콜 집계 단위

리콜 표 738행의 고유 캠페인 ID는 214개다. 144개 캠페인이 여러 행을 갖는다. 따라서 738을 독립 리콜 738건이라고 표현하거나 각 행의 잠재대상대수를 단순 합산하면 안 된다. 기존 152/738 탐지 수치는 행 단위 결과이며, 저장 판정을 캠페인별로 재집계하면 하나 이상의 행이 탐지된 캠페인은 72/214개(33.64%), 모든 행이 탐지된 캠페인은 19개다. 이는 기존 판정의 집계 단위를 바꾼 참고치이며 성능 개선·전체 차량 탐지·새로운 백테스트를 뜻하지 않는다.

## 중요 발견 3: 아직 입증되지 않은 부분

- 집계 CSV에는 원본 신고·조사의 최초 공개시점과 당시 이용 가능 정보가 없다. 미래정보 혼입이 없었다고 단정할 수 없다.
- C3/P3/S3/I3를 계산한 원본 생성 코드와 시간창 정의를 확인해야 한다.
- 2023년 말 학습행의 향후 12개월 정답은 2024년 정보가 필요할 수 있다. 단순 월 분할만으로 ML 학습과 검증 사이의 시간 누출이 차단되지 않는다.
- 모든 보유 기간이 기존 평가에 사용됐다. 보유 자료 재분석을 새로운 미사용 최종시험이라고 부르면 안 된다.
- 기존 ML 비교 스크립트는 저장소 루트의 monthly_panel.csv를 읽지만 실제 파일은 data/public 아래에 있어 이번 업데이트에서 입력을 data/public/monthly_panel.csv로 수정했다. 이번 점검에서는 해당 모델을 재학습하지 않았다.

## 다음 진행 순서

1. 기존 원본 수집·패널 생성 코드에서 날짜 정의, 수집 종료일, 신호 집계 방식을 확인한다.
2. 캠페인 단위 평가 및 중복 경보 처리 기준을 고정한다.
3. 충분한 추적기간을 확보한 구간에서 당시 공개된 자료만 사용해 정답과 신호를 재구성한다.
4. 정밀도·재현율·오경보율·선행개월을 단위와 기간별로 보고한다.
5. 별도의 미사용 자료가 확보되면 규칙을 고정한 독립 시험을 한다.

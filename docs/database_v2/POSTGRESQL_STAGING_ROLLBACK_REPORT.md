# AutoQ-Guard PostgreSQL 임시적재·롤백 시험 보고서

## 결과

| 검증 항목 | 결과 |
|---|---:|
| 시험 전 운영 테이블 대상 LOT | 0건 |
| 임시영역 유효 데이터 | 1건 |
| 트랜잭션 내부 반영 확인 | 1건 |
| ROLLBACK 후 운영 테이블 | 0건 |
| 최종 롤백 상태 | PASS |

## 시험 절차

1. 운영 `part_lot` 테이블에 시험 LOT이 없는지 확인했다.
2. 트랜잭션 내부에 임시 테이블을 만들고 신규 LOT 1건을 넣었다.
3. 중복 LOT, 협력사 존재 여부와 부품 존재 여부를 검사했다.
4. 운영 테이블 반영을 가정해 트랜잭션 내부에서 1건이 보이는지 확인했다.
5. `ROLLBACK`을 수행했다.
6. 운영 테이블에 시험 LOT이 남지 않았음을 확인했다.

## 의미

검증되지 않은 기업 데이터를 바로 운영 테이블에 넣지 않고, 임시영역과 트랜잭션 안에서 관계·중복을 검사한 뒤 승인 전에는 전부 되돌릴 수 있는 구조가 작동했다.

## 제한

- 이번 시험은 예시 LOT 1건을 이용한 기술검증이다.
- 다섯 종류의 기업 CSV를 한 번에 승격하는 통합 트랜잭션 시험은 별도로 필요하다.
- 사용자 권한별 승인, 장애 중 복구와 감사로그는 기업 환경에서 추가 검증해야 한다.

## 사용할 수 있는 표현

> PostgreSQL에서 임시 적재와 관계 검사를 수행하고 운영 반영을 가정한 뒤 ROLLBACK했습니다. 트랜잭션 내부에서는 신규 데이터 1건이 확인됐지만 롤백 후 운영 테이블에는 0건이 남아 안전한 되돌리기 구조가 작동함을 확인했습니다.

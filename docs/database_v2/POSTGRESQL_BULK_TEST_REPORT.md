## 확인된 사항

- PostgreSQL 17.10에서 기업형 12개 업무 테이블이 정상 작동했다.
- LOT 2,000개와 차량 20,000대의 관계를 데이터 손실 없이 적재했다.
- 특정 LOT 조회에 위험평가 인덱스와 차량 장착이력 인덱스가 사용됐다.
- 20개 동시 연결에서 15초 동안 442,833건을 처리했고 실패는 없었다.
- 단일 고위험 LOT에서 영향 차량 범위를 조회하는 핵심 검색경로가 정상 작동했다.

## SQLite 시험과의 관계

기존 SQLite 시험에서는 LOT 2,000개·VIN 20,000대를 처리하고 단일 LOT 평균 검색시간 0.521ms를 확인했다. PostgreSQL 시험에서는 특정 조회 실행시간 0.477ms와 20명 동시조회 평균 지연시간 0.677ms를 확인했다.

두 시험은 실행환경과 측정도구가 다르므로 숫자만으로 어느 데이터베이스가 더 빠르다고 단정하지 않는다. 이번 결과의 핵심은 PostgreSQL에서도 같은 규모의 데이터 관계와 동시조회가 오류 없이 작동했다는 점이다.

## 사용 가능한 표현

> PostgreSQL 17.10에서 2,000개 LOT과 20,000대 차량 데이터를 적재하고 20명의 동시조회 부하시험을 수행했습니다. 15초간 442,833건을 처리했으며 실패율은 0%였습니다.

## 사용하면 안 되는 표현

- 실제 자동차기업 운영환경에서 성능을 검증했다.
- 29,538 TPS가 모든 서버와 기업 데이터에서 보장된다.
- 실제 리콜 예방률과 기업 ROI가 확정됐다.

# 한계점과 기업 데이터 적용 조건

## 현재 확인된 것

- 공개데이터에서 리콜 전 선행 신호가 존재할 수 있음
- 고정 경보규칙을 시간 순서로 평가할 수 있음
- LOT 단위 공정·현장품질 결합 구조를 구현할 수 있음
- 회피손실·비용·ROI를 동일한 계산 구조로 비교할 수 있음
- 결과를 공개 관측·합성 기능시험·가정 시뮬레이션으로 분리할 수 있음

## 현재 확정할 수 없는 것

- 특정 기업 생산라인의 실제 탐지율·정밀도
- 실제 불량 LOT가 장착된 차량 범위
- 실제 출고보류 또는 리콜 범위 축소 대수
- 기업별 수리·물류·재고·보상 비용
- 실제 실현 순편익과 ROI

## 공개데이터의 한계

1. 소비자 불만은 생산공정 정보가 아니다.
2. 불만 접수량은 판매량과 신고 성향의 영향을 받는다.
3. 공개 리콜 레코드는 LOT·개별 차량 장착 이력을 제공하지 않는다.
4. 경보 정밀도 8.1%는 독립적인 자동 의사결정에 부족하다.
5. 공개데이터 결과를 국내 특정 기업의 성능으로 일반화할 수 없다.

## 합성데이터의 한계

1. 실제 공급사·설비·작업자 변동을 완전히 반영하지 못한다.
2. 결함 라벨과 신호 분포가 설계 가정에 영향을 받는다.
3. 합성데이터의 100% 또는 Gate 통과 결과는 기업 성능이 아니다.
4. 기능 오류를 발견하는 데는 유용하지만 사업성과를 증명하지는 않는다.

## 경제성 시뮬레이션의 한계

- 예방 차량 수와 성공률은 가정이다.
- 출고 후 비용과 조기조치 비용은 실제 회계자료가 아니다.
- 리콜 브랜드 손상, 법률비용, 장기 고객이탈은 완전하게 반영하지 않았다.
- ROI 확률은 입력 분포를 바꾸면 달라진다.

## 기업 실증에 필요한 최소 데이터

| 데이터 | 최소 필드 | 목적 |
|---|---|---|
| 부품 LOT | part_lot_id, part_id, supplier_id, production_time | 공급·생산 단위 추적 |
| 공정검사 | inspection_id, part_lot_id, 측정값, 시간 | 공정 이상 신호 |
| 차량장착 | vehicle_key, part_lot_id, install_time | 영향 차량 특정 |
| 현장품질 | DTC, 보증수리, 불만, 수리일 | 결함 결과 연결 |
| 비용 | 부품·공임·물류·보상·재고비 | 실제 손익 측정 |

## 기업 데이터 적용 시 달라지는 값

- 공개데이터 모델의 경보를 LOT 단위로 좁힐 수 있다.
- 판매량 대신 실제 생산·장착 대수를 분모로 사용할 수 있다.
- 오탐으로 인한 검사·보류 비용을 측정할 수 있다.
- 리콜 전체가 아니라 문제 LOT 장착 차량의 범위를 계산할 수 있다.
- 실제 회계 기준의 회피손실과 ROI를 산출할 수 있다.

기업 데이터가 들어오면 성능이 반드시 좋아진다는 뜻은 아니다. 정확한 표현은 **기업 기준의 성능과 경제성을 측정할 수 있게 된다**이다.

## 기업 어필 문장

> 공개데이터로 리콜 전 선행 신호 가능성과 분석 구조를 검증했고, 합성 LOT로 공정–차량 연결 흐름을 구현했습니다. 현재 경제성은 명시된 가정의 시뮬레이션입니다. 귀사의 내부 데이터를 적용하면 실제 탐지율·오탐 비용·영향 차량 수·직접 회피손실·ROI를 귀사 기준으로 측정하고, 기준 미달 시 확대 전에 중단할 수 있습니다.
